# Precision Discovery v1

状态：公开摘要；实验能力未默认接入生产。

## 模仿与实现

- 借鉴工业搜索的“垂直来源通道”做法，但只根据用户显式要求选择：默认`general`，明确仓库或论文时最多再加`repos`/`science`。
- 借鉴搜索引擎的官网二次导航：只从首轮真实候选推导最多2个高置信组织域名，再执行最多1轮`site:`定位。
- 借鉴浏览型检索的一跳扩展：只从已抓取的同组织页面选最多8个发布、公告、政策、数据、论文等页面链接；不递归爬站。
- 所有功能均为确定性逻辑，不调用额外LLM，不读取Benchmark答案，不建立行业路由。

## 资源边界

- 44条只用`general`，5条使用`general+repos`，1条使用`general+science`。
- 20/50触发域名二次定位，共68个二次候选；12/50产生一跳链接，共56条。
- 总Discovery请求82次，平均1.64次/问题；30条只发1次、8条发2次、12条发3次。
- 最多2个Pivot域、1轮Pivot、8条一跳链接；不递归。

## 已知限制

- 两条llama.cpp用例的冻结目标仍是旧路径`/ggerganov/llama.cpp`，而当前官方仓库已是`/ggml-org/llama.cpp`，因此Target Recall会低估实际召回。本轮没有偷改标签，以保持与历史基线可比。
- 最终页面Target Recall仍为0%，说明精确URL发现已改善候选层，但网页抓取成功与目标页正文抽取仍是下一瓶颈。
- Live A/B不是搜索引擎返回结果完全一致的离线实验；算法归因以同一运行的`initial → post_pivot → final`阶段为主。
