# Static Web Extraction v1

状态：固定快照离线 A/B；未修改生产抓取链路，未接入浏览器或 JS 渲染。

## 方法

- 30 个真实官方页面，中文和英文各 15 个。
- 覆盖文章、Release、文档、GitHub/Hugging Face、政府页面、财报入口、论文、表格、代码、JSON、Markdown、PDF 和 JS 空壳。
- Live Capture 只运行一次并保存到 Git 忽略的 `data/`；A/B 只读取相同字节快照，避免网络和页面变化污染抽取器比较。
- 每个抽取器对每个可用快照重复 3 次，记录中位耗时；150 组输出全部确定一致。
- 公开目录只保存指标、失败类型和逐例矩阵，不包含网页正文、响应头或快照文件。

| 结果 | 数量 |

## 结论

1. 当前 `Trafilatura + stdlib fallback` 混合实现仍是严格质量第一，不能直接换成单一库。
2. Resiliparse 平均快约 7.4 倍，正文召回相当，但日期只有 20%，导航泄漏更高；适合下一阶段作为候选快速正文通道，而不是直接替换。
3. Trafilatura 的作者/日期和导航清理最好，但列表、表格和部分中文政府页会过度抽取或返回空。
4. jusText 与 Readability 可作为特定页面补充，不适合作为统一默认抽取器。
5. 静态空壳已能用通用页面特征识别；是否对少量页面启用浏览器必须在后续 4B-2 单独授权后评测。

## 已知边界

- 本结果衡量固定快照抽取，不衡量搜索召回、答案质量或浏览器渲染。
- 耗时是本机单进程、固定快照、中位数，仅用于同次 A/B 排序，不等同于生产 P99。
- 两个 Live Fetch 失败不进入抽取器质量分母；其失败仍保留在抓取成功率中。
- `current` 会调用 Trafilatura 并在必要时退回 stdlib，因此它是现有混合链路，不是独立算法。
